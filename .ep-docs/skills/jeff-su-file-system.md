# jeff-su-file-system (Jeff Su 방식 파일 시스템 정리 스킬)

Desktop, Downloads, 공유 드라이브, 외장 저장소 같은 물리적 파일 시스템을 Jeff Su 방식으로 정리하고 새 파일/폴더도 올바른 위치로 선제 라우팅.

## When to use
- 폴더 구조를 새로 설계해야 할 때
- 새 문서/폴더를 만들기 전에 유지 가능한 저장 위치와 구조를 먼저 잡아야 할 때
- Downloads/Desktop/Drive를 정리해야 할 때
- 기존에 어지러운 폴더 트리를 dry-run 또는 안전한 범위 내 실제 정리로 재정리해야 할 때
- 파일명 규칙을 통일해야 할 때
- 진행 중인 것과 종료된 것을 분리해야 할 때
- Jeff Su 방식, 5레벨, 99 아카이브 규칙을 적용하고 싶을 때

## When NOT to use
- 코드베이스 디렉터리 구조를 강제로 재편할 때
- Notion/Confluence/wiki의 페이지 계층이나 DB 구조를 설계할 때
- 사진 앨범/미디어 라이브러리처럼 다른 정리 기준이 더 자연스러운 자산을 다룰 때
- DB 스키마, 문서 정보구조, 태스크 그래프 같은 논리 구조를 설계할 때
- 단순 검색만으로 충분하고 재구조화가 필요 없을 때

## Core Rules
- 폴더는 최대 5레벨까지만 허용
- 우선순위/활성도 기준 폴더는 `01_`, `02_` 같은 두 자리 번호 사용
- `99_archive/`는 완료/비활성 자료 전용이며 `99`는 archive 외 용도로 재사용하지 않음
- 시간 순서가 더 중요한 자료는 연도/분기/월 기반 네이밍 허용
- 파일은 실제 사용되는 프로젝트/컨텍스트 안에 둠
- 과도한 세분화보다 단순한 구조 우선

## Scope Boundary
- 드라이브/폴더/파일 배치와 naming 문제에는 사용
- 문서 앱 내부 페이지 구조나 정보구조 문제에는 사용하지 않음

## Workflow

```
현재 트리 점검 → 생성 시점 라우팅 vs 기존 트리 재정리 분기 → 검색 방식 분류(우선순위/시간/키워드) → 5레벨 이하 구조 설계 → 활성/비활성 분리 → 파일명 규칙 정리 → 안전한 변경은 실제 적용, 큰 변경은 dry-run 결과 제시
```
