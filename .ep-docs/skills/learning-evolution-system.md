# learning-evolution-system (학습 진화 시스템)

배운 내용을 회수 가능한 지식 체계로 승격하는 운영 스킬. YouTube/로컬 영상 학습 노트, 사용자 피드백, 회의/문서/업무 회고에서 배운 내용을 구조화하고, 도메인 지식 번들에 편입하며, 현재/과거/미래 업무 적용 가능성을 분석.

## When to use
- YouTube/로컬 영상에서 배운 내용을 업무 지식으로 바꾸고 싶을 때
- 사용자 피드백, 회의, 회고에서 배운 점을 체계화하고 싶을 때
- 반복되는 실수나 운영 개선점을 기본 규칙으로 승격하고 싶을 때
- 기존 지식과 새로운 지식이 충돌해서 사람 검토가 필요할 때
- 개발/마케팅/재무/SEO 같은 도메인 지식 번들에 배움을 편입하거나 새 번들을 만들어야 할 때

## When NOT to use
- 단순 메모만 남기면 충분하고 재사용 구조화가 필요 없을 때
- 코드 구현/버그 수정이 주목적일 때
- Notion/Confluence 같은 앱 내부 정보구조만 설계할 때

## Core Operating Model

8단계 워크플로:
1. **입력 원천 식별** — 출처 링크, 파일 경로, 날짜 기록
2. **학습 후보 정규화** — 1~3문장 요약 + 중요성 + 도메인 연결
3. **도메인 번들 분류** — 기존 번들 편입 vs 신규 번들 생성 판단
4. **적용성 분석** — 현재/과거/미래 업무 적용 가능성
5. **전파 대상 분류** — global rule / global skill / project-local memory 중 어디로 갈지
6. **충돌 검사** — 기존 승인 지식과 모순 여부 확인
7. **인간 검증 요청** — Slack으로 승인 요청 (충돌 비교 + 전파 대상 선택지 포함)
8. **승인 후 승격** — ep-memory로 도메인 파일 merge + 인덱스 갱신

## Domain Knowledge Bundle Model

낱개 메모가 아닌 도메인 지식 번들 단위로 관리:
- 개발 지식, 마케팅 지식, 재무 지식, SEO 지식, 디자인 지식, 브랜딩 지식 등
- 새 지식이 들어오면: 기존 번들 편입 / 새 번들 생성 / 인간 선택지 제시
- 전역(global) + 프로젝트(local) 동시 유지 모델

## Source Intake Types
- `youtube-to-notes` 결과물
- 사용자 피드백 / 회의 기록 / Slack 스레드
- 문서 / 리서치 결과
- 업무 회고 / 작업 후 교훈

## Safety
- 신규 지식은 모두 인간 검증 후에만 승격
- 충돌 시 비교 요약 + 추천안 함께 제시
- 확신 없으면 project-local first로 보수적 제안
